Filters · 2

Option A

Search gets its own line

Search is full width; everything you toggle sits on one row beneath it. Active filters appear as chips in that same row, immediately left of the button, so state and the control that changes it are adjacent. The gear becomes the word "Filters" with a count.

Two rows instead of three; nothing hidden.

With 3+ active filters the row wraps and you're back to three rows.

Option B

No button at all — a chip rail

Delete the drawer. Every filter is a chip in one horizontally scrolling row; tapping one turns it on and jumps it to the front, so what's active is always the first thing you see. This is what Google Maps and Airbnb do on a phone.

Zero hidden state, one row, filtering is one tap instead of three.

Off-screen chips are genuinely undiscoverable; needs a scroll cue.

Filters · 2

Option C

Bottom bar, sheet opens upward

Filters leave the header entirely and become a bar pinned to the bottom of the screen, showing active filters inline. Tapping it slides a sheet up. The one option that puts the control where your thumb already is — the top-right corner is the hardest place to reach one-handed, which matters at a restaurant table.

Header shrinks to two rows; dishes start higher.

The most code — a new sticky element and a sheet; desktop needs a fallback.

Option D

Filters as tokens inside the search box

Active filters become removable tokens inside the search field, with the gear at its right edge. Search and filtering are the same idea — both narrow the list — so this says that out loud: one box holds everything narrowing what you see.

Truly two rows no matter how many filters; strongest "this is why the list is short" signal.

Tokens eat the typing space; fiddly on a small screen and the least conventional.

If you want a recommendation

B for the phone. It's the only one that removes a step rather than relocating it — no drawer to open, active state unmissable, one row of chrome. A is the cheap, safe version if deleting the drawer feels too drastic; C is the most mobile-correct and the most work. Worth deciding alongside #27, since the at-a-restaurant view has the same problem.
